# Техническое задание: голосовой ассистент «Соня»

## 1. Идея проекта

Локальный голосовой ассистент под Windows, работающий по триггер-слову ("Соня, ..."),
распознающий команду, понимающий её смысл через LLM (Gemini API) и выполняющий действие
(запуск игр/программ, системные команды), с голосовым ответом. Адаптируется под текущую
нагрузку на GPU (важно во время игр) и засыпает при простое.

Визуальная модель (VTuber-аватар) — отдельный этап, вне scope v1.

## 2. Технологический стек

- **Язык:** Python 3.11+ (лучшая экосистема под все нужные ML/аудио библиотеки)
- **Wake word:** openWakeWord (лёгкий, опенсорс, работает постоянно в фоне)
- **STT:** faster-whisper (модель `small`/`medium`, поддержка CUDA и CPU)
- **NLU/мозг:** Gemini API (google-genai SDK) — разбор намерения, роутинг команд
- **TTS:** Silero TTS (torch.hub, русский голос, легкий)
- **Голос (опционально, этап 2):** RVC inference поверх Silero для анимешного тембра
- **Мониторинг ресурсов:** pynvml (загрузка GPU/VRAM), psutil (CPU/RAM)
- **Аудио ввод/вывод:** sounddevice / pyaudio
- **Конфиг:** PyYAML + python-dotenv (.env для API-ключей — НЕ в репозитории)

## 3. Архитектура (модули)

```
sona/
  wake_word/       — детектор триггер-слова, всегда активен, минимальная нагрузка
  stt/              — распознавание речи, адаптивный выбор устройства (GPU/CPU)
  brain/            — интеграция с Gemini API: разбор команды -> intent + параметры
  executor/         — выполнение действий (запуск .exe, погода, поиск, файлы и т.д.)
  files/            — доступ к файлам: поиск/открытие/чтение/создание, системные и
                      чувствительные каталоги (Windows, Program Files, AppData и т.п.)
                      заблокированы на уровне кода; удаление/перемещение не реализовано
  tts/              — синтез речи (Silero), опционально RVC-конвертация тембра
  resource_monitor/ — опрос нагрузки GPU/CPU, принятие решения GPU vs CPU для STT/TTS
  power/            — таймер простоя (15 мин без команд -> сон, выгрузка моделей из VRAM/RAM)
  orchestrator/      — главный цикл: слушает wake word -> STT -> brain -> executor -> tts
  config/           — конфиги: пороги нагрузки, алиасы программ, таймауты, общий загрузчик алиасов
main.py             — точка входа
```

### Поток выполнения

1. `orchestrator` держит активным только `wake_word` (низкая нагрузка, постоянно слушает).
2. Услышав "Соня" — активирует полный пайплайн: пишет аудио команды, передаёт в `stt`.
3. `resource_monitor` перед этим определяет: GPU свободен -> STT/TTS на GPU; GPU занят
   (порог VRAM, например >75%) -> переключение на CPU.
4. Текст команды уходит в `brain` (Gemini API) с системным промптом, который знает список
   известных программ и возвращает структурированный intent (JSON): `launch_app` — запуск
   программы, `get_weather` — погода (данные берёт бесплатный Open-Meteo), `web_search` —
   вопросы про актуальные события (бесплатный Tavily), `answer_question` — вопрос из
   собственных знаний Gemini (математика, факты и т.п.), `unknown` — не поняла.
   В интернет уходит только текст самой команды и короткий поисковый запрос для
   `web_search` — содержимое файлов и личные данные наружу никогда не передаются.
5. `executor` выполняет действие (запуск процесса, HTTP-запрос к погоде/поиску и т.д.)
   и возвращает результат/подтверждение.
6. `tts` озвучивает ответ. Все ответы начинаются с фирменной фразы "Да, хозяин, ..."
   (например: "Да, хозяин, запускаю", "Да, хозяин, не нашла такую программу").
7. `power` сбрасывает таймер простоя при каждой обработанной команде; если 15 минут
   тишины — выгружает тяжёлые модели (STT/TTS/brain-сессию) из памяти, оставляя только
   wake word детектор.

## 4. Нефункциональные требования

- Никаких секретов (API-ключи) в репозитории — только через `.env`, с `.env.example` как
  шаблоном.
- Скачиваемые веса моделей (Whisper, Silero, RVC) — не коммитятся, только documented
  auto-download или инструкция.
- Логи, временные аудиофайлы, venv — не в репозитории (`.gitignore`).
- Понятная структура для последующего добавления визуального аватара (VTube Studio) как
  отдельного модуля без переписывания ядра.

## 5. Этапы (roadmap)

- **v0.1** — ядро: wake word + STT + Gemini brain + базовый executor (запуск программ по
  алиасам) + TTS (Silero) + resource monitor + сон по таймауту. Работает из консоли.
- **v0.2** — RVC-конвертация голоса поверх Silero: максимально человечный, милый тембр
  (требуется референс-датасет голоса для подбора/адаптации RVC-модели).
- **v0.3** — визуальный аватар: рендер через VTube Studio (готовое решение с прозрачным
  фоном, always-on-top, click-through и lip-sync по аудио) — модель (Live2D, формат
  `.model3.json`) предоставляет пользователь. Наш TTS/RVC-звук маршрутизируется в VTube
  Studio для синхронизации рта. Свой рендерер с нуля не пишем — VTube Studio уже закрывает
  все требования (поверх всех окон, шевеление ртом).

Данное ТЗ покрывает v0.1. Голос (v0.2) и аватар (v0.3) — приоритетные следующие этапы,
архитектура `tts/` и будущего `avatar/` модуля закладывается уже в v0.1, чтобы не
переписывать ядро.

## 6. Wake word — выбор движка (заметка)

Изначально планировался openWakeWord с кастомным обучением модели под "Sonya"/"Sonechka"
через Google Colab. Отказались после нескольких попыток: официальный и сторонние
пропатченные ноутбуки упираются в отсутствие сборок `piper_phonemize` под Python 3.13
(текущий рантайм Colab) на нескольких независимых источниках пакета подряд, плюс
исчерпание бесплатной GPU-квоты Google в процессе. Пробовали переключиться на
**Porcupine (Picovoice)** — но их self-service консоль в 2026 стала чисто энтерпрайзной
(требует "company email", отклоняет обычную почту, вместо бессрочного бесплатного
тарифа — 7-дневный триал).

Итоговое решение — **Vosk**: маленькая (~50 МБ) офлайн-модель распознавания речи,
скачивается напрямую без регистрации. Вместо отдельного бинарного классификатора
слушаем поток распознанного текста и ищем в нём кодовые слова — заодно это дало
нативную поддержку кириллицы "Соня"/"Сонечка" без транслитерации на английский,
которая требовалась для openWakeWord/Porcupine.
